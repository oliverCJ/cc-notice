# AI 工具输入清单

实现前必须收集或验证以下事实。公开工具优先使用官方文档；官方资料不足时，必须要求用户提供可复现配置样例、payload 样例和触发步骤。

## 来源证据

记录：

- 官方产品或 CLI 文档 URL
- Hook 或事件系统文档 URL
- 配置文件路径和配置格式文档 URL
- 全局配置说明 URL
- 项目级配置说明 URL
- Hook handler 命令格式说明 URL
- payload 字段说明或示例 URL

同时记录：

- 已由官方资料确认的事实
- 用户提供信息与官方资料的冲突
- 官方资料不完整时采用的假设
- 仍需要用户确认的缺失事实

## 工具身份

必须确认：

- 稳定 `source`，使用 kebab-case，例如 `codex`、`claude-code`
- 用户可见展示名
- 工具命令或应用名称
- 支持的平台和配置路径差异
- 是否支持全局 Hook 配置
- 是否支持项目级 Hook 配置
- 项目级配置如何定位项目根目录
- 同一用户多项目配置是否可能互相影响

## Hook 事件

每个 Hook 事件必须确认：

- 原始事件名，保持工具官方大小写
- 中文标题
- 用户可理解的描述
- 典型使用场景
- 是否推荐默认启用
- 默认映射到哪个内置内部事件
- 触发条件
- 手动触发步骤
- 是否可能高频触发
- 是否需要节流、降噪或不推荐默认启用

推荐 Hook 应优先覆盖：

- 会话开始或用户提交提示
- 工具调用前或任务执行中
- 权限请求或等待用户输入
- 工具调用失败或任务失败
- 当前轮次结束或任务完成

## Hook 配置

必须确认：

- 全局配置文件路径
- 项目级配置文件路径
- 配置文件格式：JSON、TOML、YAML 或其它
- Hook handler 所在字段路径
- 是否支持多个 handler
- handler 命令是否需要 shell 包裹
- 工作目录、环境变量和 stdin 行为
- 如何识别 CC Notice 托管 handler
- 如何保留用户已有 handler
- 如何安全移除 CC Notice 托管 handler
- 配置写入后是否需要重启工具或重新加载项目

## Relay 与 Payload

必须确认：

- Hook handler 调用 `cc-notice-relay` 的命令格式
- `--source` 值
- `--event` 值
- payload 从 stdin、参数还是文件传入
- 真实 payload 样例
- payload 中可稳定使用的字段
- 无法匹配现有白名单变量、但对用户有价值的字段
- 字段别名如何映射到模板变量：
  - `tool_name`
  - `model`
  - `prompt`
  - `tool_response`
  - `last_assistant_message`
  - `pwd`
  - `sessionId`
  - `permissionMode`

不要为了复用现有变量而做错误语义映射。例如工具的 `command` 字段不能默认伪装成 `tool_name`；若确实需要展示命令，应在接入设计中提出新增或扩展内置变量的方案。

## UI 和模板

必须确认：

- Hook 设置页是否需要展示独立工具 tab
- 全局目标和项目目标的展示名称
- 默认推荐 Hook 列表
- 基础模板需要新增哪些 AI 映射
- 完整模板需要新增哪些 AI 映射
- AI 映射画布中工具节点的标题和摘要
- Debug、诊断和运行监控是否需要新增文案

## 缺失资料时

向用户索取：

- 实际配置文件样例
- 真实 Hook payload 样例
- 每个推荐 Hook 的触发步骤
- 项目级配置写入后的实际触发结果
- 工具版本号和平台
